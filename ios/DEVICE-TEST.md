| 检查 | 预期 |

- [ ] 小支主页 → 支首页（斜向蓝带）
- [ ] 总资产 → 总资产页（很长的滚动页）
- [ ] 余额 → 余额页
- [ ] 余额宝
- [ ] 花呗
- [ ] 支付消息
- [ ] 个人信息
- [ ] 切换账号
- [ ] 财富页 → 理财页
- [ ] 收款记录
- [ ] 小荷包
- [ ] 芝麻信用

**微页签** 前几格应该进 WebView（小微主页）：

- [ ] 第 1 格 → 出现「微信」聊天列表（**这一条最关键**：验证 `app://` 下 ES module 能否加载）

> ⚠️ 如果 WebView 那格是**白屏**，就是 `app://` + ES module 的已知风险点。
> 告诉我，我把加载方式改成「本地回环 HTTP 服务」—— 改动只在 `WebHost.swift` 一处。

## 三、网络与账号（DTW 私有协议）

- [ ] 「我」页点「点击登录 / 注册」→ 弹出登录表单
- [ ] 用测试号登录（`resettester` / `newpass9876`）
- [ ] 登录成功后「我」页显示昵称、VIP 卡状态变成真实值

> 登录走的是 DTW 隧道（握手 + AES-GCM 帧 + 序列号防重放）。协议已用 Node 镜像打过生产 20 项全过，
> 但**日 Swift 实现本身从未运行过** —— 这一条是验证网络层的第一现场。

**如果登录失败**，请把 App 控制台日志里带 `[DoutuApi]` 的那几行发我。

## 七、回报格式（省你打字）

```
✅ 启动、四个页签、宫格 12 格：都正常
❌ 微页签第 1 格：白屏
❌ 登录：提示「网络异常：The request timed out」
   日志：[DoutuApi] 请求失败 POST /api/v1/auth/login → ...
⚠️ 我页 VIP 卡：金色按钮位置偏右下约 8px（截图见附件）
```

有截图最好 —— 我能用几何比对把偏差量化到像素。两种工具：

**① 两个已标定过的页面**（「我页」「娱乐页」）用现成的特征块比对：

```bash
python _ios/compare_geometry.py       # 我页：4 个特征块
python _ios/compare_geometry_ent.py   # 娱乐页：4 个特征块
```

**② 其余 25 屏**用通用截图比对（出包后每屏一条命令）：

```bash
python _ios/compare_shots.py \
  --android _ios/golden_home.png \       # Android 真机截图
  --ios     _ios/iphone_home.png \       # iPhone 截图（同屏）
  --align --out _ios/diff_home.png
```

输出会告诉你：
- **整体平均差（0-255）** —— `< 6` 且最差条带 `< 40` 就算这一屏过关
- **最差 20 个横向条带** —— 标 `<<<` 的那一段就是结构偏差所在（多半是某个卡片位置或字号）
- **并排 + 差异图**（`--out`）—— 左 Android、中 iPhone、右差异 ×3

它自带缩放（都归一到宽 1080）与自动对齐（±30px），所以两台设备分辨率不同、
截图边框差几像素都不影响。**我已经用「同一张图比自己」（差 0.00）和
「人为偏移 18px」（能定位、能自动对齐）验证过这个工具本身**。

截图建议：同一屏、都在**列表顶部**（未滚动）状态拍，这样最可比。
